# 等长批的 Packed Prefill 慢在哪里

在共享 RTX 4090 上运行 Qwen3-0.6B、FP16。每批均有 1,024 个有效输入 token。复测中，8 条等长 128 token 的请求走原打包路径时，整批首 token 延迟比普通补齐路径分别多 5.47 和 7.48 ms。分别改变输入整理、K/V 缓存布局、注意力调用，三项改动都能缩小差距。

## 每次只改一项

同一轮、同一批输入先后运行各方法。下表取每轮两次计时的差，再取 30 轮配对差的中位数。正数表示实验条件相对原打包路径节省的毫秒数。不同改动单独测量，收益会受 GPU 调度、内核选择及数据布局影响，各行不可直接相加。

| 相对原打包路径的改动 | 8 × 128 首次 / 复测 | 4 × 256 首次 / 复测 |
| --- | ---: | ---: |
| 计时前准备好连续 token、位置、序列边界和缓存槽位 | 2.98 / 2.39 | 2.27 / 2.29 |
| 每层将等长 K/V 直接视作分好的行，省去清零缓冲区与按槽位拷贝 | 2.79 / 2.70 | 2.63 / 2.67 |
| 仅将变长注意力调用换成等长因果 SDPA，保留打包投影和缓存路径 | 2.50 / 2.37 | 2.43 / 2.90 |
| 普通补齐路径相对原打包路径的完整优势 | 5.47 / 7.48 | 7.31 / 7.41 |

第一项模拟上游已经提供打包输入的条件。它衡量从计时范围内移除这段工作能节约多少，分词器直接输出打包格式后的端到端收益仍待单独测量。第二项仍调用 Transformers DynamicCache 的更新接口，变化仅发生在更新前的行布局准备。第三项包含形状转换和两种调用接口自身的开销。

另在独立诊断轮中用 CUDA events 标记打包输入、逐层缓存整理、缓存更新及注意力调用。以 8 × 128 为例，两次运行中，原打包路径的输入整理中位耗时为 2.51 / 2.32 ms，28 层变长注意力调用累计区间为 5.61 / 9.61 ms，对应的普通注意力区间为 2.69 / 2.65 ms。事件记录的是 CUDA 流上的时间区间，可能包含提交空隙及其他负载造成的等待；加标记的运行与正式端到端计时分开。[首轮原始数据](seed-211.json) · [复测原始数据](seed-227.json)

## 把输入整理放回计时

每次重新拼接输入并构造位置和边界。等长输入使用一次连续编号生成行内位置；变长输入通过序列边界反查每个 token 的请求编号。两次独立运行各做 24 轮，以下仍取配对差的中位数，正值代表节省耗时。

| 批大小与最长输入 | 单改在线输入整理，首次 / 复测 ms | 在线整理加等长缓存视图，首次 / 复测 ms |
| --- | ---: | ---: |
| 8 × 128，等长 | 0.56 / 0.44 | 2.67 / 2.81 |
| 4 × 256，等长 | −0.06 / 0.23 | 2.61 / 2.39 |
| 8 × 160，填充占比 20% | 0.10 / −2.02 | 不适用 |
| 8 × 768，填充占比 83.3% | 0.40 / −0.04 | 不适用 |

在线重写输入整理对两种变长负载均未产生可重复的收益。等长 K/V 已按请求顺序连续排列，更改形状即可供解码使用，原实现逐层整理并复制这部分数据的成本可以避免。8 × 128 同时使用两个改动后，普通补齐仍分别快 3.28 / 2.13 ms。高填充的 8 × 768 输入在四轮独立实验中一直由原打包路径更快。[在线首轮](seed-251.json) · [在线复测](seed-269.json)

## 验证与复现

四个进程使用不同种子，每个形状、每个进程预热所有方法后交错测量。各方法在完整顺序周期中均匀轮换位置。正式计时共 1,632 次，测量范围从 token 已在设备上到整批首 token 就绪。绝对毫秒值会随共享设备负载变化，各次采集前后的 GPU 快照保存在原始 JSON。

正确性检查使用每种形状六个随机种子，比较首步全部 logits 和随后共四个生成 token。在线整理相对原打包的 336/336 条请求四步输出一致，所有首步 logits 差值均为零。在线整理加等长缓存视图的等长子集为 144/144。这里的参考是已有打包实现，逐条完整重算的参考结果见[上一组实验](../variable-batch-4090/README.md)。诊断改动仅在实验脚本运行期间启用。

```bash
python scripts/profile_prefill_cost.py --model /path/to/Qwen3-0.6B --seed 211 --output first.json
python scripts/profile_prefill_cost.py --model /path/to/Qwen3-0.6B --seed 227 --output repeat.json
python scripts/profile_prefill_cost.py --model /path/to/Qwen3-0.6B --online --seed 251 --rounds 24 --output online1.json
python scripts/profile_prefill_cost.py --model /path/to/Qwen3-0.6B --online --seed 269 --rounds 24 --output online2.json
```
