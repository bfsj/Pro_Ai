# Qwen3 变长批生成实测

在一张共享 RTX 4090 上以 FP16 运行 Qwen3-0.6B，每批收到 1,024 个有效输入 token，每条请求贪心生成 4 个 token。比较统一补齐、按长度分桶和打包三种路径。首轮与复测的六种形状中，等长输入均由统一补齐更快地给出整批首 token，长短混合输入均由打包路径更快。

## 性能

后续实验将输入整理、K/V 写回和注意力调用分别做配对对照，结果见[等长批的打包耗时分解](../prefill-cost-4090/README.md)。

单位为毫秒。首轮和复测均在预热后交错执行 12 轮，遍历三种方法的六种顺序两次。每格取该方法该形状的中位数。批首 token 指批内所有请求的第一个 token 都已就绪，计时包含整理输入、左填充或打包、KV 写回与采样。端到端时间覆盖全部四步生成。输入 token 已在设备上，分词、网络与在线排队在计时范围外。

| 批大小与最长输入 | 填充占比 | 首轮补齐 | 首轮分桶 | 首轮打包 | 复测补齐 | 复测分桶 | 复测打包 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 4 × 256 | 0% | 38.70 | 38.72 | 45.54 | 35.78 | 35.77 | 41.58 |
| 4 × 320 | 20% | 57.91 | 107.03 | 49.96 | 51.23 | 94.40 | 44.29 |
| 4 × 896 | 71.4% | 56.65 | 126.54 | 36.73 | 127.79 | 146.02 | 48.25 |
| 8 × 128 | 0% | 31.00 | 31.07 | 35.38 | 37.88 | 37.91 | 43.08 |
| 8 × 160 | 20% | 42.83 | 83.59 | 37.76 | 58.89 | 108.06 | 49.74 |
| 8 × 768 | 83.3% | 89.28 | 213.26 | 37.36 | 191.79 | 232.68 | 44.02 |

8 条高差异请求在首轮的四步总延迟由 208.70 ms 降至 161.20 ms，下降 22.8%。打包仅改变 Prefill，解码继续使用稠密 DynamicCache。等长批几乎没有填充可省，打包、整理缓存仍需工作。当前分桶实现按桶串行前向和解码，批越碎，重复调用模型的成本越高。两次运行的绝对耗时波动明显，数据来自共享设备。原始文件包含逐轮时间、P95 和各形状前后的设备利用率快照。[首轮数据](primary.json) · [异种子复测](repeat.json)

## 正确性

参考路径逐条运行模型，每一步完整重算已知前缀。随机 token 输入按九个种子和六种形状构造，共 54 批、324 条请求实例。每种方法复用同一组输入。下面的“四步一致”要求一条请求的四个生成 token 全部匹配。另选两个种子复测的 72 条请求，三种方法均为 72/72。

| 首轮方法 | 首 token 一致 | 四步一致 | 对齐位置中相同 token |
| --- | ---: | ---: | ---: |
| 补齐 | 323/324 | 318/324 | 1284/1296 |
| 分桶 | 323/324 | 321/324 | 1288/1296 |
| 打包 | 323/324 | 322/324 | 1289/1296 |

单独重放两条打包差异。第一条的逐条参考在第一步出现两个同分候选，打包路径将二者拉开 0.0078125；第二条在解码第 2 步首次分叉，参考的前两名仅差 0.0078125，打包路径逆转了次序。将同批其他请求的所有 token 改掉后，两条目标请求各自的首步 logits 和四个生成 token 都与原打包运行完全一致。这项检查支持这两个样本的请求隔离，尚不能定位舍入差异具体来自哪个 kernel。随机输入上的贪心匹配率只用于执行路径对照。[重放记录](packed-mismatches.json)

## 按填充占比选路

填充占比取 `1 − 有效 token 数 / (批大小 × 批内最大长度)`。根据前两轮结果，固定阈值为 20%，再以两个新种子测试六组此前未测的形状。每种方法各计时 12 轮。阈值显式传入；在支持 Flash 的 CUDA 半精度环境中，达到阈值才选打包，CPU 使用补齐。

| 请求长度 | 补齐 ms | 打包 ms | 自动 ms | 自动选择 |
| --- | ---: | ---: | ---: | --- |
| 4 条，各 128 | 35.87 | 43.05 | 35.92 | 补齐 |
| 105、123、140、144 | 61.27 | 50.53 | 59.46 | 补齐 |
| 72、98、161、181 | 50.81 | 43.24 | 43.26 | 打包 |
| 8、20、40、444 | 41.00 | 35.47 | 35.52 | 打包 |
| 92、104、116、120、132、140、152、168 | 41.62 | 43.97 | 45.32 | 打包 |
| 16、32、48、64、80、96、176、512 | 55.19 | 35.62 | 35.45 | 打包 |

按两条固定路径的批首 token 中位数比较，自动选择在 4/6 种新形状上选中较快者。11.1% 填充的四请求批和 23.8% 填充的八请求批分别在阈值两侧选错。仅用填充占比不足以捕捉批大小及运行环境的影响，因此保留手动选路和显式阈值。新形状上自动路径的完整输出与逐条重算有 63/64 条一致。[留出实验原始数据](held-out.json)

## 复现

以下命令在仓库根目录、已安装本项目及 CUDA 版 PyTorch 2.11 的环境中执行。各命令需要新的输出文件名。

```bash
python scripts/benchmark_batch_generation.py --model /path/to/Qwen3-0.6B --output primary.json
python scripts/benchmark_batch_generation.py --model /path/to/Qwen3-0.6B --seed 92 --seeds 2 --output repeat.json
python scripts/audit_packed_differences.py --model /path/to/Qwen3-0.6B --input primary.json --output audit.json
python scripts/benchmark_batch_generation.py --model /path/to/Qwen3-0.6B --seed 113 --seeds 2 --validate-threshold 0.20 --output held-out.json
```
