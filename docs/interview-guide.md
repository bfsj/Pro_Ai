# 面试讲解与简历使用

## 60 秒项目介绍

“我围绕一个 Qwen3 模型搭建了单卡推理实验框架，比较无缓存、动态和静态 KV Cache，使用固定输入逐位置验证 logits，并设计预热、交错重复测量和显存统计。在此基础上实现并接入 Triton RMSNorm，同时比较 eager、torch.compile 和完整模型的结果。项目交付包含原始数据、性能曲线和可复现命令。”

根据你实际掌握的范围调整“搭建/实现”等动词。项目有 AI 辅助，不能将框架提供的缓存或尚未理解的代码说成独立从零实现。

## 最可能被追问的内容

1. KV Cache 缓存的是哪些张量？GQA 中为什么用 KV 头数计算显存？
2. 首 token 来自哪里？为什么生成 N 个 token 后缓存只有 L+N-1 个位置？
3. 静态缓存的空槽位为什么不能参与 Attention？测试如何发现漏掉 mask？
4. 同一序列的 FP32 logits 接近，而 BF16 失败，能得出什么结论？
5. 是否公平比较了最后位置投影、输出 buffer、输入长度与生成数量？
6. 为什么 GPU 测速要同步？为什么 Profiler 不能一直开着测正式性能？
7. 额外峰值、allocated、reserved 和 nvidia-smi 显存有什么不同？
8. Triton RMSNorm 每个 program 处理什么，如何处理非 2 的幂宽度？
9. 为什么要与 torch.compile 比较，而不能只与多算子 eager 比较？
10. 算子快了 2 倍，端到端一定快 2 倍吗？请用时间占比解释。
11. 为什么静态缓存没有必然收益？容量、mask 和 Attention backend 分别影响什么？
12. 如果要变成线上推理服务，还缺请求到达率、队列、公平性、取消、持续批处理、限流等哪些能力？

## 简历条目写法

最终数字见 `docs/experiments/` 的实测报告。按实际配置写：

> **单卡 LLM 推理与算子优化实验平台（Python / PyTorch / Triton）**
>
> 实现显式 Prefill/Decode 循环，集成动态与静态 KV Cache，建立逐位置 logits 验证与自动化测试；设计固定工作负载与交错重复基准，分析推理吞吐、缓存显存和数值差异；实现并接入 Triton RMSNorm，结合算子与端到端对照解释性能收益及适用范围。

选两三个最有代表性的实测配置补充数值：精度、batch、输入/输出长度、硬件和比较基线必须能说清楚。不要把实验中的最大倍数概括成所有场景的普遍收益。

## 归属与范围

- 预训练模型：Qwen3；模型结构与 Cache 类：Transformers；参考学习：nano-vLLM、Triton 官方教程。
- 本项目代码包含 AI 辅助。你应能独立运行、定位函数、解释核心逻辑并维护自己认领的部分。
- 没有实际 PR 就不要写“贡献 vLLM”；没有线上部署就不要写“生产服务”；单卡实验不要写成多卡分布式系统。
