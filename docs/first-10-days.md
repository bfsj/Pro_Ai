## 阅读代码顺序

1. `core.forward_last`：最小模型调用与最后位置 logits。
2. `core.decode`：完整 prompt 前向、缓存更新、逐 token 生成、计时。
3. `core.check_cache`：固定输入序列，比较两种执行路径。
4. `benchmark.run_benchmark`：工作负载、预热、重复测量与结果保存。
5. `report.plot_report`：从原始结果生成可比较曲线。

在改变优化开关之前，固定模型、精度、Attention backend、输入长度、输出长度和硬件。一次实验只改一个你想研究的因素。

## 本阶段需要答清楚的问题

- Prefill 如何生成第一个 token？为什么 N 个输出只有 N-1 个后续 Decode 步？
- 缓存保存了什么，省掉了哪些重复计算，还保留了哪些随上下文增长的工作？
- 为什么应比较相同输入下的 logits，而不能只看生成文本是否相同？
- 总吞吐提高是否意味着单条请求的延迟下降？
- GPU 异步执行、预热、数据搬运会怎样影响计时？
- 为什么最后一个生成 token 不在本轮结束时的 KV Cache 中？
- GPU 显存不足时，权重、缓存、临时张量各扮演什么角色？
